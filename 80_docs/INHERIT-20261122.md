## 一、一句话架构

> 一只**页面内挂件**：React 组件注册到 `conversation.composer.dock` 槽位，
> 用 base64 内嵌的 150 张精灵贴在输入框右上方；同进程里跑一个本地 HTTP 服务
> （`127.0.0.1:43717`）提供配置、用量、命令、商店，页面每 2–5 秒轮询它。

没有后端、没有数据库、没有模型调用。**全部零 token。**

## 六、状态机与时序

```
t=0                     sleepMs            sleepMs + FIT_FRAMES*frameMs
├──── sleep ────────────┼──── fitting ──────┼──── idle ──────────────────────▶ ∞
│ 小恐龙被子             │ 8 格试衣间条带     │ 坐在金砖上（四季自动 / 皮肤）
│ 呼噜泡 8.5s 周期        │ 帘子闭合瞬间切形态  │ 打字→笔记本姿势；眨眼；思考云
│ 慢呼吸 5.2s            │                   │
```

- 计时基准是**模块级 `LOADED_AT`**，槽位重挂载不重置；`config.resetAt` 可以强制重来
- 覆盖优先级：`force`（CLI/面板） > 状态推导；`force` 3 秒后自动解除
- doze：4 分钟无活动且页面隐藏 → 回 sleep
- 监督（escalate）：空闲 `idleMs` → 第 1 级 → 每 `stepMs` 翻倍 → 占满锁定 → 点它弹窗 → 确认复位

**形态（form）判定**：`outfits.force` 手动（数字 0–3 / `'pajama'` / 皮肤 id） > 夜间 23–07 睡衣 > 季节映射。

## 九、⚠️ 难改点（这次的重点）

按"改一处会牵动几处"排序。**前人不是不会写，是这几处结构把后续改动卡住了。**

### 难点 1：加一套皮肤要动 5 个地方，漏一处静默失效

```
① 出 8 张图（4 姿势 × 戴/不戴奶嘴）
② make_sitter_plugin.py 的 SPRITES 加 8 行
③ client.template.js 的 SKIN_IDS 加 1 个 id
④ host.template.js 的 SKIN_CATALOG 加 1 条（价格/描述/emoji）
⑤ nopac_* 链路逐条核对（formSprite 是字符串拼接，拼错不报错，只是回退到别的图）
```
**症状**：新皮肤在商店里能买，穿上没变化（回退到 idle0），没有任何报错。
**建议**：把皮肤定义收敛成 `skins.json`（id/价格/描述/素材前缀/姿势清单），构建期校验
"声明了的姿势必须有图"，缺图直接**构建失败**而不是静默回退。

### 难点 2：所有贴图 base64 内嵌 → 单文件 7.4 MB

`client.js` 7,433,853 B = 150 张图。后果：
- 改**一张图**就要重写 7.4 MB 文件、重新 Copy、重新开关插件
- 页面加载要解析 7.4 MB 源码 + `new Image()` 150 次解码
- 想"按需加载皮肤"或"动态扩充动作库"在当前结构下**做不到**

**建议**：把贴图从 JS 里搬出来，走 `dsh-app://` 静态资源或宿主 `/sprite?key=` 接口，
client.js 只留 key → URL。这一步做完，上面难点 1 的 ②③ 会合并，加皮肤降到 2 处。

### 难点 3：姿势是写死的三条 if 分支

`formSprite` 里 `pose` 只认 `idle | blink | typing | typingblink`。
`40_actions` 里的 hit/squat/thinking/ultraman 想接进来，没有"播放一段序列"的通用通道。
**建议**：引入 `pose` 注册表 `poseName → {frames:[key...], fps, loop}`，状态机只产出 poseName。

### 难点 4：状态机是"渲染期 if/else"，不是显式 FSM

`state = elapsed < sleepMs ? 'sleep' : elapsed < sleepMs+FIT_MS ? 'fitting' : 'idle'`，
再加 3 处 force 覆盖、2 处 doze 覆盖，然后是**三个 early return 各画一套 UI**。
加第 4 个状态要同时改推导逻辑 + 新增一个 return 分支 + 想清楚它和 owner/calibrate 的关系。
**建议**：`state = reduce(events, {now, agent, input})`，UI 层按 state 查表渲染。

### 难点 5：参数是"扁平 RT + 手写 40 行映射"

加一个参数要改 4 处：`config.default.json`、`RT` 初值、`applyConfig`、使用处。
而且 `applyConfig` 里已经有**重复键**（`workLink` 写了两遍，后覆盖前），说明手写映射已经开始腐化。
**建议**：RT 直接由 `deepMerge(DEFAULTS, userConfig)` 得到，去掉手写映射。

### 难点 6：整组件 120ms 一次 setState

`setNow(Date.now())` 每 120ms → 永久 8.3fps 重渲染，每次重渲染都重跑 `currentForm()`、
`formSprite()`、重建 20 多个 style 对象。现在能跑，但这是"加任何功能都变慢"的根源。
**建议**：把 `now` 换成只在**状态边界**触发（sleep→fitting→idle 三个时间点各一个 setTimeout）。

### 难点 7：宿主路由手写，异步回调不在 try 里

这次崩了 5 次就是它（详见 `RED-LINES.md` 红线 7）。加任何新路由都可能重演。
**建议**：把路由收成表 `{path, method, handler}`，统一 `safeHandler()` 包装；
或者干脆换 `node:http` 之上的一层极简封装。

### 难点 8：设置页面板硬编码 43717

`WardrobePanel` 里 6 处写死 `http://127.0.0.1:43717`，而宠物本体走 `API_BASE`（会探测 43717–43720）。
宿主一旦漂到 43718（旧实例没退干净时会发生），**宠物正常、设置页全哑**，而且面板不报错。
**建议**：面板也用 `resolveApi()` 的 `API_BASE`。

### 难点 9：绝对路径写死

`make_sitter_plugin.py` 第 18 行 `ROOT = Path(r'D:\DSH-Pet')`；
`pet-cli.mjs` 里 `'D:/DSH-Pet/scripts/check_client.mjs'`。
换机器 / 换盘只有这两处挡着，改起来很便宜。

### 难点 10：没有版本控制 + 素材无出处

- `D:\DSH-Pet` 不是 git 仓库，60+ 个 `_*.py` 是"当时改了什么"的唯一记录
- `10_base` 411 个文件里只有 150 个在用；`sitting_hoodie` vs `sitting_hoodie_clean`、
  `think_cloud` 三个版本、`blink3.backup.png`、`ultra0_dark` —— **哪张是定稿看不出来**

## 十一、如果要做 v2，建议顺序

1. **先 `git init` 提交基线**（0.5 天）—— 没有它，任何重构都是赌博
2. **贴图外置**（难点 2）—— 打开这一步，难点 1/3 才有解
3. **素材清单 JSON 化 + 构建期校验**（难点 1）—— 缺图构建失败，不再静默回退
4. **状态机显式化**（难点 4/3）—— 之后加动作、加形态才是加法而不是改 if
5. **宿主路由表化 + 统一异常包装**（难点 7）
6. **配置映射自动化**（难点 5）
7. 面板走 `API_BASE`（难点 8）、路径去硬编码（难点 9）、`_*.py` 归档（难点 10）

前 3 步做完，"加一套皮肤 / 加一个动作"就从"改 5 个文件 + 赌"变成"加一条 JSON + 放图"。
这也是它现在最像"上一版难改"的地方。
