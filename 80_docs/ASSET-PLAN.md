# 桌宠素材生产方案（v1）

> 目标：用最少的出图次数，产出一套能自由组合的表情 + 衣服 + 配件素材库。
> 所有素材统一画布、统一像素网格、统一调色板，靠脚本合成，不靠 AI 反复生成组合。

---

## 一、核心原则：分层，不做组合

素材一共四层，各自独立生成、独立修改：

```
10_base/body.png            素体（灰色素体衣 + 白色 AF1）
30_clothes/bottom/*.png     下装图层（对齐到同一画布）
30_clothes/top/*.png        上装图层
20_face/*.png               表情图层（只覆盖脸部区域）
35_acc/pacifier.png         奶嘴（开/关 = 有图层/无图层）
```

合成顺序：`body → bottom → top → face → pacifier`

**为什么这样做**：如果按「衣服 × 表情 × 奶嘴」直接出图，是 5 上衣 × 4 下装 × 12 表情 × 2 奶嘴 = **480 张**；
分层只要 **1 + 4 + 12 + 1 = 18 张**，剩下的 480 种组合由脚本合成，**0 次 AI 调用**。

## 三、出图策略（省 token 的关键）

1. **一次出图 = 一组**：表情按「一种情绪 × 3 档」排成一行，一张图裁出 3 张；上衣按 2×2 网格，一张出 4 件。
   → 表情 4 次 + 上衣 2 次 + 下装 1 次 + 奶嘴 1 次 ≈ **8 次出图**，而不是 18 次。
2. **永远不重新生成已有层**：缺哪件补哪件，参考图用「已定稿的素体」，保证同一套画风。
3. **核对只看拼版**：脚本把新素材拼成一张总览图，我只读这一张判断要不要返工，不逐张读图。
4. **文案不进图**：台词、人设、气泡都写配置文件，图里不出现任何文字。
5. **锁定参数**：画布 640×360、像素网格 1px、调色板 16 色、人物站位固定，全部写进脚本常量，避免每次调参。

**预算对比**：直接出组合 ≈ 480 次调用（约 15 万 token 出图 + 28 万 token 核对）；
分层 ≈ 8~10 次调用（约 1 万 token + 3 张核对图）。**省 95% 以上**。

## 五、合成与动画流水线

```
层素材(PNG) → compose.py 合成静态图(480 种组合)
            → anim.py 生成帧序列（呼吸 / 点击 / 睡觉 / 走路）
            → ffmpeg 编码 VP9-alpha webm（640×360, 24fps）
            → dsh-pet pet pack（pet/<种类>-config.json + pet/<种类>-animation/*.webm）
            → 打包进独立 exe 或直接替换数据目录
```

**已跑通**：`tools\ffmpeg\ffmpeg.exe`（VP9-alpha）+ Python 3.12 + Pillow，640×360 透明 webm 已验证可解出 alpha。

**动画最小集**（先用脚本变换生成，后续可替换成手绘帧）：

| 动画 | 触发 | 内容 |
|---|---|---|
| `idle` | 待机 | 上下浮动 + 轻微挤压 |
| `click` | 被点击 | 弹一下 + 切表情 |
| `work` | 任务进行 | 小幅左右晃 |
| `sleep` | 睡觉 | 三段：入睡 / 循环 / 醒来 |
| `walk` | 漫游 | 位移 + 上下颠 |

## 八、运维技巧：改完素材怎么生效

- **只改 pet pack 的动画/贴图**：刷新 DSH 页面即可，客户端会重新拉取。

  会重启桌面 Helper 并按最新配置重建窗口，**不用重开 DSH**。

## 九、分身问题定位结论（2026-11-19）

现象：屏幕上出现两个一模一样的宝宝。

定位过程与证据：

1. 枚举顶层窗口，发现同一进程里有两个同名窗口：
   `pid 34752 True "dsh-pet 桌宠（桌面模式）" 840x747` × 2
2. 但进程只有一个 Electron helper → 排除「残留进程」。
3. 读插件日志的判定行：
   `桌面判定：pets=7，桌面可见=2（qiu1,xia1）`
4. 读客户端源码 `src/client/pet/multi.ts:180`：
   `overlay 只渲染 display 为 web 或 both 的宠物`
5. 读宿主源码 `src/host/plugin/desktop/pets.ts:16`：
   `display === 'desktop' || display === 'both'` 才建桌面窗。

结论：**不是代码 bug，是多只宠物的 display 同时开启**。
当时的状态是 baobao1=web、xia1=desktop、qiu1=desktop —— 网页里一只 + 桌面上两只，
而夏装/秋装是同一个角色，所以看着像分身。

另外，`display: both` 天生就是两只（页面浮层 + 桌面透明窗各一只），
做桌宠时应固定用 `desktop`。

修复：新增 `scripts/set_pet.py`，强制「只有一只可见」。用法：

```
python scripts/set_pet.py baobao     # 戴奶嘴版
python scripts/set_pet.py qiu        # 秋装
python scripts/set_pet.py --list     # 查看当前状态
```

切换后执行一次 `POST /dsh-pet-7340/reload`。

改动后验证：`桌面可见=1（baobao1）`，窗口枚举数量 = 1。
