## 一、先回答"为什么今天下午一直在重启"

**不是模型问题，也不是会话太长。是插件宿主自己把应用打死。**

证据：`%APPDATA%\@deepseek-ai\dsh-desktop\logs\crash-*-host.log`，
今天 **5 次**完全相同的签名（本地时间）：

| 时间 | 崩溃 |
|---|---|
| 15:56 | host exited with 1 |
| 16:02 | 同上 |
| 18:00 | 同上 |
| 18:18 | 同上（前任最后一个 turn 就是死在这里） |

```
dsh: fatal uncaught exception: Error [ERR_HTTP_HEADERS_SENT]:
  Cannot write headers after they are sent to the client
    at ServerResponse.writeHead
    at @local/dsh-sitter/index.js:535:17
    at IncomingMessage.<anonymous> (index.js:659:7)
```

### 根因链条（三个 bug 叠在一起）

1. **`POST /cmd` 引用了越界变量**
   `index.js:541` 写 `cmd: pendingCmd`，但 `pendingCmd` 是 `/state` 分支里的 `const`（第 551 行）。
   → 抛 `ReferenceError`。

2. **`readBody` 的回调抛错后会二次调用 `done()`**
   ```js
   try { done(raw ? JSON.parse(raw) : {}); }
   catch { done({}); }        // ← done 抛错后又被调一次
   ```
   第一次调用已经 `writeHead(200)`，第二次走到 `writeHead(400)` → `ERR_HTTP_HEADERS_SENT`。

3. **异步回调不在 `handle()` 的 try/catch 里**
   `req.on('end', …)` 是事件循环里的回调，外层 `try` 早就返回了。
   异常变成 `uncaughtException` → **dsh desktop host 进程 exit 1** → 主进程重启 host → 页面/GUI 端口全换。

**谁触发**：`node scripts/pet-cli.mjs check` 一定会打 `POST /cmd`（第 85/108/270 行）。
所以"跑一次体检 = 重启一次应用"。这也解释了前任反复出现的"改了没反应、好像没生效"。

### 附带发现的第二处（同一批补丁造成）

`/state` 第 551–559 行：取走命令后 `lastCommand = null`，却又 `return cmd: lastCommand`。
→ **命令通道永远是 `null`**：CLI 的 `play`、面板的放大/督促/复位、`selftest` 全部静默失效，且不报错。

      `_fix_heartbeat.py`、`_add_rules.py`）交叉改同一批文件，其中两个逻辑重叠、互相打脸
      （这正是本次 P0 的来源）。**建议第一步就 `git init` + 把当前状态提交成基线。**

### P1（功能静默失效 / 卡顿）

- [ ] **源码与安装副本长期不同步**。我接手时 `dsh-sitter/client.js` 是 18:17:59 的构建，
      安装副本还是 17:59:25 —— 前任最后一条命令（构建→安装）正好被 18:18 那次崩溃腰斩。
      跑的是旧代码，查的是新源码，这类"改了没反应"会反复出现。
      **建议**：把 `构建 → preflight → 安装 → 校验哈希` 合成一个脚本，别靠手打四行。
- [ ] **`/stats` 仍然同步解压**。`computeStatsAsync()` 只是把 `readFile` 换成异步，
      `decodeFrames()` 依旧是逐帧 `zstdDecompressSync`。实测（今日 12 个会话、33.8 MB、37791 帧）：
      **主线程一次冻结 1317 ms**，其中最大的会话单独占 446 ms。缓存 60 s，所以每分钟卡一下。
      `/stats` 跑在 host 进程里，卡久了同样会被看门狗收掉。
      修法：把统计改成增量（记录上次读到的 offset / 只解尾部）、或挪到 `worker_threads`。
- [ ] **异步回调的裸写还没清干净**。这次只加固了 `readBody` 和 `/stats`。
      今后任何新路由只要在 `.then()` / 事件回调里写 `res`，都会重演同一出。
      **规则：`res` 的第一笔写必须在 try 里，且整条响应路径只能有一次。**
- [ ] **`/hello` 探针在插件热重载后为空**。客户端只在模块挂载时 POST 一次 `/hello`，
      重载后新宿主实例收不到。而 README 明确说"判断新代码是否生效先看看探针"——
      于是每次重载都会误判成"新代码没生效"。修法：客户端每 30 s 心跳一次。
